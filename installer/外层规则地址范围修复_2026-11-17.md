# 外层规则地址范围修复（addressfix1）

## 实际故障证据

2026-11-17 的 diagnostic3 实机脱敏记录：阶段 set-remote，组件 VirtualBoxVM.exe，ARGUMENT，HRESULT 0x80070057。先前的 add-rule 失败只是汇总提交时暴露，同一参数问题在分步创建后被定位到 RemoteAddresses。

旧表达式为 `0.0.0.0-126.255.255.255,128.0.0.0-255.255.255.255,::/0`。其中 IPv6 `/0` 不符合 Windows 防火墙协议的子网要求（前缀范围为 1 到 128）。离线假对象此前未覆盖此原生约束，不能据离线通过宣布实机修复。

## 代码调整

- 将地址表达式改为非零前缀的等价子网列表；IPv4 首项使用 0.0.0.1/2，IPv6 下半区使用 ::2/1，避免用未指定地址作为输入字面量。掩码计算后的覆盖范围保持：IPv4 除 127.0.0.0/8 之外的全部地址，以及全部 IPv6 地址。
- 从纯文本相等改为规范化后的地址区间覆盖相等，兼容 Windows 的 IPv4 点分掩码、条目顺序及 IPv6 格式变化。拒绝通配符扩大范围、缺失区间、格式错误和无界输入。
- 在规则仍禁用时读取并验证地址范围，全部成功后才启用；失败仅清理本次新建、身份匹配且仍禁用的规则。
- 保留任务端口、程序路径、入站 UDP、阻止动作及配置文件限制；不以删除保护或关闭防火墙避开错误。

## 已完成验证与限制

addressfix1 的 C# 自测 165 项通过、0 失败，包含新增 7 项地址及登记回归。独立 Python ipaddress 校验确认地址覆盖集合相等。未登记的 Windows 原生 FWRule 对象可接收新表达式，原生 getter 将 IPv4 CIDR 转为点分掩码，校验已兼容该形式。

最初上述离线测试未调用 INetFwRules.Add。随后本人在 addressfix1 中继续原任务并反馈地址范围错误消失；脱敏管理员结果为 exit=0 / done / 0x00000000，独立只读回读两个任务规则、三类防火墙开关及地址覆盖均通过。真实虚拟机和浏览器完整流程仍待验收。仓库配置状态为 Locked，维护工具未修改主机防火墙、网络或真实虚拟机。
