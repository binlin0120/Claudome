## 结论

审查发现并处理了以下具体缺陷；当前仍不能发布已验收正式版。关键路径审查不等于对全部第三方依赖的安全认证。

| 等级 | 触发与原有结果 | 本次处理 | 验证 |
|---|---|---|---|
| P1 | VirtualBox 向来宾复制随机名的私有输入/脚本并重命名为 payload.json、Configure.ps1 时，总把完整文件路径传入 --target-directory，目录语义错误，可能复制失败或落到错误位置 | 目标以反斜杠结尾才用目录选项，单文件重命名使用源与目标位置参数 | 2 项模拟 VBoxManage 命令检查，不调用真实虚拟机 |
| P1 | Clash Verge 全局 config.yaml 会逐键覆盖专用 profile 的 TUN；全局旧 auto-detect-interface=true / strict-route=false 可能破坏总线绑定或严格路由 | 全局配置同步专用 TUN、DNS、物理接口及混合端口；移除不适用的旧物理接口 | 导入真实纯配置函数，验证全局旧值被纠正、DNS 保留代理与无效输入不写入 |
| P1 | 从已有任务切换到未保存资料的任务时，旧密码、订阅、节点及 API Key 留在表单；下次读取可能混用 | 载入经验证的任务前清空私有字段、节点选择与镜像识别；只有明确加载的目标任务资料可回填 | 2 项 WPF 场景，均为虚构资料，无 DPAPI 真实资料读取 |
| P1 | 未载入原状态、直接把安装目录改为已有任务目录时，新 WorkspaceId 可能与已有 VM 混用 | 续装必须匹配原任务 WorkspaceId 和目录，不符时要求先载入原状态 | 模拟不同身份、不同目录与合法尾部路径分隔符 |
| P2 | 重试时新增安装器出站规则会被禁用，但原回退清单只写一次，撤回可能遗漏后禁用的规则 | 每次禁用前将本次规则名与已记录规则去重合并并保存；配置后的补充检查同样记录 | 验证首轮、重试、新规则、空列表与重复项往返，不修改真实防火墙 |
| P2 | 点击载入任务后取消文件选择，原代码已先关闭当前网关 | 改到文件已选定且身份、路径验证通过后再撤回网关 | 源码路径审查；真实网关/窗口交互仍待实机验收 |
| P2 | Hyper-V 映像阶段中断留下 VHDX，重试仅返回笼统 DISK_SCOPE，右侧仍鼓励重复继续 | 保留原磁盘，单独标识磁盘恢复待办，取消该待办上的无意义继续/启动按钮 | 源码解析、错误分支检查；只改善诊断，不声称已实现自动恢复 |

## 发布阻塞项与修复状态

1. **Hyper-V 映像阶段的恢复缺口（P1，recovery1 源码已修复，待实机验证）**：原审查发现 Guest/HyperVWorker.ps1 的 Install-WindowsDisk 仍会在发现已有磁盘且没有 .windows-applied 完成标记时暂停。必须补齐带任务/磁盘身份校验的检查点恢复，或清晰、经用户确认且保留原磁盘的重建流程。不得通过删除磁盘或跳过 DISK_SCOPE 检查解决。本轮未执行磁盘恢复操作。
2. **VMware 初始配置中断恢复缺口（P1，recovery1 源码已修复，待实机验证）**：原审查发现 Workstation.Configure 在写入 VMX 后、machine 完成阶段保存前若发生中断，重试遇到现存 VMX 会直接停止。需增加验证已有 VMX 与本任务磁盘/资源/隔离设置一致后幂等继续的路径，并注入断点测试。不得无条件覆盖已有配置或忽略 TPM/加密状态。
3. **三平台真实安装、通道和驱动尚未验收**：离线无法证明官方安装器行为、Guest Additions/Tools、Hyper-V Socket、VMCI/vSockets、UDP 防护规则、ISO 与 Wintun 在真实 Windows 上按预期工作。
4. **实际打开与隔离破坏测试尚未完成**：包括正常启动、暂停/保存状态/关机恢复、应用关闭后重连、停止 Clash、来宾管理员改防火墙、主机/局域网/直连探测；所有平台分别记录结果。
5. **AdsPower 与 Claude 业务验收尚未完成**：必须由使用者完成登录/API 权限等人工环节，在专用浏览器核对出口、DNS、WebRTC、地区时区并实际登录、对话，不能用软件安装报告代替。
