# 安装 DNS 与桌面等待修复（unified5）

## 已确认的故障和证据边界

本人在 unified4 的原任务中继续后，收到 BOOTSTRAP_DNS_FAILED。代码路径显示失败发生在虚拟机启动前的安装网络探测。旧版本只调用 1.1.1.1 的 DoH，把 SOCKS、TLS、HTTP、解析等各种失败合并为 DNS_FAILED；该码不足以认定节点失效。桌面页的静态“正在自动连接”也没有跟随暂停和网络错误更新，且未显示安装资源下载/节点准备进度。

主机普通请求中，1.1.1.1 与 dns.google 的 DoH POST 均返回有效 DNS 消息，原查询 ID 可被回显；此检查没有使用客户节点，也不能据此说明客户代理通路已经恢复。原故障究竟来自节点通道还是 DNS 服务可达性仍需新版经实际节点重试。

## 修改

- 使用 cloudflare-dns.com 与 dns.google 两个独立 DoH 服务，分别固定拨号到 1.1.1.1:443 与 8.8.8.8:443，域名只用于 HTTPS Host/SNI/证书校验。两者都经认证回环 SOCKS 和本人选定的同一个节点，不自动切换节点、关闭证书校验或使用主机 DNS/直连。
- 并行请求、统一期限，任一有效应答即可继续；DoH 查询按 RFC 8484 使用 ID 0，并在回到来宾时恢复原 ID，校验问题、类型、响应标记、Content-Type 与长度。拒绝无效响应及跳转。
- 分别保留认证、代理连接、HTTPS 证书、传输中断、服务 HTTP 错误、响应校验、空地址、超时、后续 Windows HTTP 联网探测等错误。只输出固定错误码和中文说明，不输出原始异常、节点地址、查询响应或凭据。失败仍保留原任务和磁盘。
- 桌面页增加“继续原任务并连接”，需要重新确认安装范围时明确转到对应页面。恢复操作立即清除暂停显示；当前操作、下载信息和进度在桌面页可见。失败后保留具体提示，停止继续显示无限连接；本人关闭后的自动重开限制继续保留。

## 验证

最终 EXE 标准检查 304 项通过、0 失败（C# 177、离屏 WPF 37、PowerShell 89、VirtualBox CLI 契约 1）。Go 网关 35 项测试通过，包括实际回环 SOCKS 认证和 TLS 的 DNS 往返、备用服务成功、期限、ID/问题校验及固定错误码。离屏图逐项检查暂停、网络准备进度和网络失败三个状态。

证据保存在工作区 `output/安装网络DNS修复_2026-11-17/` 的 `verification-summary.json`、`go-tests.jsonl`、`preview/desktop-*.png`；ZIP 另检查白名单、CRC、解压哈希和解压 EXE 自测。源码维护没有执行实际部署、修改主机网络或读取真实凭据。

新版仍需本人用原任务继续验证实际节点、首次设置联网和真实控制台接入；本轮测试不等于实机问题已消失。其他平台、Win10 客户机和完整浏览器业务范围沿用此前待验收状态。
