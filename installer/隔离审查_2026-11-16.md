# 安装助手的隔离审查（开发中，尚不能交付）

> 历史记录：下文描述当时的构建与测试。当前审查结论、修复及发布阻塞项见[发布前审查与修复（2026-11-17）](发布前审查与修复_2026-11-17.md)。

本次检查的是尚未发布的 `installer/ClaudeSetup` 源码和官方平台文档，没有在客户或本机重新安装虚拟机，没有运行真实订阅，也没有改变主机网络。代码编译通过不等于隔离或自动安装验收通过。

## 文件传送和软件安装的含义

- 由主机程序核验并下载 VirtualBox、微软运行库、Windows 官方媒体创建工具等平台所需组件；Hyper-V 是 Windows 可选功能。VMware 官方下载如要求登录，由客户在官方页面完成。
- 向本次选定的来宾复制 PowerShell 7、Clash Verge Rev、AdsPower 的安装资源及固定配置脚本；网络输入只传所选节点，API Key 仅在需要时传给该来宾。不会把整份主机用户目录、浏览器资料或主机系统盘映射进去。
- 文件复制使用对应平台的 Guest Control / PowerShell Direct / VIX，由主机发起；没有设计常驻共享文件夹。指定来宾返回少量安装与检测 JSON 报告，不把来宾返回的文件当主机程序执行。
- 自动安装 Windows 时，临时应答介质包含可还原的来宾密码。Base64 编码不是加密；需要限制文件访问，并在安装完成后弹出、删除且验证。异常中断时还要检查残留。

## 威胁模型和可承诺范围

按最严格的常用情况考虑：来宾内可能运行可执行命令的 Claude / 其他 Agent，并可能获得来宾管理员权限。不能把“来宾不会修改防火墙”作为前提。

目标是阻止来宾访问主机文件、主机服务和局域网设备，并防止代理失效后直接访问业务网站。普通 Claude 网页本身不因此自动获得主机磁盘权限；但有命令或电脑操作工具的 Agent，其能力取决于实际授予的权限。

不承诺隐藏“正在虚拟机内运行”这一事实、所有 CPU 特征、账号之间的关联，也不承诺任何虚拟化产品零逃逸漏洞。指纹浏览器和代理无法提供这些保证。

## 早期版本发现（历史审查）

| 等级 | 风险 | 源码现状与影响 | 必须完成的处置 |
|---|---|---|---|
| 严重 | NAT 不构成主机 / 局域网阻断 | VirtualBox、Workstation 使用 NAT；Hyper-V 选择 Windows 默认交换机。没有完整的虚拟机外部访问控制，不能证明主机各网卡地址、NAT 特殊地址或局域网服务不可达 | 在来宾之外建立默认拒绝的边界。私有虚拟网络加受主机管理的网关是一种候选；Hyper-V 虚拟交换机 ACL 需按独立方案实现和实测 |
| 严重 | 来宾管理员可修改保护 | 现有 Clash 和 Windows 防火墙保护均在 Windows 来宾内。管理员可改规则、停服务或改路由 | 出站最终放行权必须位于来宾之外，并验证修改来宾防火墙后依然不能探测主机 / 局域网 |
| 高 | 安装及启动阶段存在未保护窗口 | Windows 首次启动、软件安装器自动启动、旧页面恢复都可能发生在来宾保护配置之前 | 在任何来宾程序联网前启用外部策略；重启和恢复同样先核对隔离再放行，未满足时保持阻断 |
| 高 | 地址与 DNS 绕行 | 原解析逻辑未排除私网节点、DNS 返回的内网地址；IPv6、链路本地、主机其他地址需要单独验证 | 已增加公网 IPv4 端点限制。仍须在外部边界控制 DNS、全部网卡、IPv6、重解析、主机公网地址等路径；地址过滤本身不是完整隔离 |
| 高 | 管理 / 集成功能扩大接触面 | Guest Additions、VMware Tools、PowerShell Direct、虚拟显示与设备都属于信任边界；Hyper-V 初始化当前会短暂启用再移除 WinRM 网络监听 | 优先使用非网络管理通道；初始化也必须在网络隔离后执行。关闭不必要的剪贴板、文件拖放、共享文件夹、USB、增强会话重定向、远程显示和设备直通，并回读实际设置 |
| 高 | 临时秘密与脚本可见性 | 来宾内节点配置、浏览器会话、API Key 对同一来宾管理员不保密；Windows 安装应答介质可还原来宾密码 | 只传部署必需字段，不复用主机账号密码和主机浏览器资料；安装输入及时清理并核验；不能宣称对来宾管理员隐藏已交给来宾的软件凭据 |
| 中 | 网络隔离不消除账号 / 云同步关联 | 本人复用账号、AdsPower 云环境或浏览器同步，可能重新带入身份与历史数据；代理服务商也能观察其连接来源 | 新建专用环境，不自动导入主机浏览器用户资料；登录、同步及云数据范围由本人确认；不保证账号不可关联 |
| 中 | 虚拟化及硬件特征可见 | 来宾可读到虚拟设备、虚拟化标记，以及平台暴露的部分 CPU 等信息；这不等于主机文件已暴露 | 明确对外承诺边界；不把指纹浏览器称为整机安全隔离，也不声称任何主机特征都不可推断 |
| 高 | 非网络的宿主信息通道 | Hyper-V KVP 通过 VMbus 交换元数据，VirtualBox Guest Additions 也有属性通道；断开网卡不代表这些信息不存在 | 逐平台检查宿主描述、集成功能及缓存；限制不必要的数据交换，并验收必要的安装管理通道。不能据当前研究认定 Cage 或本项目已完全遮蔽这些信息 |
| 残余 | 虚拟机逃逸及供应链漏洞 | 隔离依赖宿主系统、虚拟化软件、驱动和来宾工具的正确实现 | 使用官方、校验过且受维护的版本，减少设备和集成功能；如业务要求更强边界，应评估独立物理设备或远端隔离环境 |

## 隔离放行所需证据

1. 列举主机各网卡、NAT 特殊地址、局域网和链路本地范围，确认来宾无法访问主机 HTTP、SMB、RDP、本机代理和其他监听服务；覆盖 IPv4 与 IPv6，不将一次连接超时当成全部通过。
2. 验证不存在主机磁盘映射、共享文件夹、剪贴板文件、拖放、USB 直通和增强会话驱动器重定向；返回报告不能触发主机执行。
3. 在本次专用测试来宾中关闭或修改来宾防火墙、停止代理、尝试其他 DNS 和直接路由，确认外部边界依然阻断未获准路径。
4. 对冷启动、登录、重启、恢复、代理失效和节点更换分别验收，确认不存在先联网后补保护的窗口。
5. 确认专用浏览器出口、DNS、WebRTC、时区；再由本人登录 Claude。浏览器检测不能替代主机隔离测试，主机隔离测试也不能替代账号与业务验收。

## 2026-11-17 开发进展

以上表格与无条件部署拦截描述保留为历史问题。当前源码已接入 Hyper-V Socket、VMware VMCI / vSockets 与 VirtualBox UDP 三条通路，去除普通 NAT / 桥接兜底；启动前、恢复与租约续期均回读边界，失败保持关闭。VMware 离线模式也检查剪贴板、HGFS 与 USB。Hyper-V 增强会话为主机全局策略，增加单独告知、明确确认、原值记录、多任务归属和关机后恢复；安装与持续检查使用独立管理通路。

还补充了来宾交互桌面调度、镜像身份与版本选择、按操作随机标识绑定的新报告验证。记录与当前能力以[完整部署接通与验证](完整部署接通与验证_2026-11-17.md)为准。此轮没有实际安装、真实规则应用、真实通道或对抗探测，因此上述实机验收要求仍然有效；不声明完全隔离。
