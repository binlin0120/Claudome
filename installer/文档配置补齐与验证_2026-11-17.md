# 文档配置补齐与验证

构建：`0.3.0-dev.20261117.aligned1`。本轮修复源码、运行虚构资料的离线检查并生成客户体验包；没有安装或启动真实虚拟机，没有导入真实代理、账号或 API Key。部署会话文件缺失，按 Locked 处理；仅在仓库维护范围工作。

## 修复内容

| 原先缺口 | 本次实现 | 结果边界 |
| --- | --- | --- |
| 只接受独立节点 | 最终出口与前置节点分开选择；两跳使用 `dialer-proxy`，固定 SelectedNode，不生成 DIRECT 回退；外层只允许前置地址/端口；两端域名分别固定解析地址 | 直接引用独立节点的两跳配置可导入；动态策略组、循环、多跳及外部插件明确拒绝，需拆开选择 |
| 订阅可能沿用缓存节点 | 部署前按原节点名称刷新；最终和前置任一节点消失或链式关系改变就要求重新确认 | 不自动选择替代节点；任务载入保留导入链式关系，不将其变成不会刷新的旧前置 |
| AdsPower 只写参数 | 美国请求语言设置为 en-US、en；其他地区按选定出口设置；WebRTC 禁用、城市时区、自动匹配 UA/内核；使用同一归属标记的专用环境 | 不读取 Cookie、账号页面或浏览器存储；运行中的原窗口先提示保存关闭，避免带着旧参数继续使用 |
| 中文翻译与请求语言未区分 | 在专用窗口的设置页通过 Chromium 设置接口设置并读取翻译开关、简体中文目标；不改请求语言来实现翻译 | 分支内核不支持设置接口时留下具体待办，不伪报自动成功；翻译服务实际联网仍待体验 |
| 未测真实浏览器参数 | 随机回环页面读取真实 Accept-Language；页面回读语言、时区、仅本地 ICE 候选；比较 UA 与 Browser.getVersion 的主版本 | 不采集原始 UA/IP；本地 ICE 检查不代表公网 DNS/IPv6 泄露检查已经完成 |
| 重开没有验证 | 官方 API 正常关闭并确认 Inactive，再用原 profile ID 启动回读，中间不更新配置 | 仅自动关闭本步骤自己刚启动的原本关闭窗口；原本已打开的用户窗口保留，提示保存后另验 |
| 重启前先修复可能掩盖持久化失败 | 独立“重启虚拟机并检查”入口，先读当前配置，正常请求来宾重启；启动时间必须改变；重新登录后只回读，不先运行配置函数 | 保持助手和外层网关开启；待登录时保留重启基准，继续回读不会再次重启；重新配置会作废本次重启证据 |
| 断线只验证桌面请求 | 先验证桌面和同一专用浏览器的联网基线；停实际内核并检查未自行恢复，分别验证断网；恢复后核对两端出口 | 缓存/Service Worker 绕过被禁用，创建独立检测标签；没有有效基线或浏览器可旁路时不算通过 |
| Clash 开机配置入口不明确 | 独立当前用户开机入口，原值备份；回退时恢复原值或移除本次入口 | 来宾服务/TUN/规则/选定配置须在重启后实际回读；AdsPower 客户端按需启动以检查持久环境，不宣称无人登录自动就绪 |
| 脚本隐藏失败 | 修复原 Configure-Clash 中将只读 `$HOME` 当目录变量的错误；新增函数改为 `$clashHome` | 新增全体来宾脚本的保留变量赋值检查；异常只输出脱敏待办 |

“检查已配置环境”“断线与恢复检查”“重启虚拟机并检查”均独立于重新部署。相关待办优先提供“检查现有配置”，重新配置入口明确标为“重新配置后再验收”，避免无意覆盖待验证状态。

## 客户仍需实际完成

真实 Windows 安装、三平台原生通道、Clash/AdsPower 当前版本兼容性、服务开机、实际断线和重启，需要在客户选定虚拟机中执行验证。冷启动/保存状态恢复、越过来宾防火墙后的外层隔离探测、指定检测页的公网 DNS/IPv6 等检查、本人的 Claude 登录与对话，没有在本轮实机执行，不计为通过。

开发中发现并修正两项回归：运行内核检查抓到原有 `$HOME` 只读变量错误；实际界面回归抓到新增前置选择器没有接入既有 ComboBox 模板。修正后重新运行针对检查及最终整套检查，报告只引用最后通过的结果。
