## 下载续传、安装进度与旧盘清理

下载资源保留已下载分片，按服务器支持续传并核验 SHA-256；已有 ISO 校验后复用。资源下载、Windows 系统写入与虚拟磁盘是不同阶段，不会因为重试安装而默认重新下载整个 ISO。

新 Windows 启动、来宾工具和身份确认通过后，程序自动删除本任务清单中已被新盘替换的旧半成品盘。删除前检查目录、任务、当前盘、虚拟机和快照引用；文件仍被占用时记录待清理项并提示，下次继续时重试。不会清理客户的其他虚拟机或安装资料。

界面显示下载百分比、安装阶段和等待时间；Hyper-V 写入系统时接收 DISM 的真实百分比。VirtualBox / VMware 安装期间拿不到整体百分比时显示等待指示，并提示查看真实 Windows 安装窗口，不编造 40% / 80% 等总进度。详细行为与离线证据见[旧盘清理与安装进度](旧盘清理与安装进度_2026-11-17.md)。

## 三个平台的接入

| 平台 | Windows 与来宾软件 | 虚拟机外的网络通路 | 需要本人处理 |
|---|---|---|---|
| VirtualBox | 官方资源自动获取和校验、无人值守 Windows、Guest Additions、Clash / AdsPower | 首张网卡只连接受控 UDP 网关，其他网卡关闭；按 VM 端口和 VirtualBox 进程限定主机入站规则并回读 | Windows 许可、UAC、浏览器账号登录 |
| Hyper-V | 按版本检查及启用可选功能、二代 VM / TPM / 安全启动、离线应用 Windows、PowerShell Direct、来宾软件 | 没有普通虚拟网卡；经认证的 Hyper-V Socket 和来宾 Wintun 接入同一受控网关 | 功能重启、UAC、关闭主机增强会话策略的单独确认、账号登录 |
| VMware Workstation | 识别并核验官方安装器、VMDK / VMX、Windows 应答介质、Tools、VIX 来宾配置 | 没有普通网卡；VMCI / vSockets 与来宾 Wintun 接入同一受控网关 | 官方下载登录、首次加密 / vTPM、UAC、账号登录 |

以上是代码能力概述，三平台整套闭环仍需分别按实机验收记录为准。Mac 的 Fusion / Parallels / UTM 教程继续保留；Windows 版 `Claudome.exe` 不直接在 Mac 或 Windows ARM 主机上运行（Mac 端独立工程见 `installer/Claudome.Mac`，尚待真机验收）。已有虚拟机只读取注册信息，不覆盖或自动接管其他项目。

## 客户操作范围

1. 运行程序，检查资源，选择推荐的平台和独立任务目录；可扫描已注册的虚拟机。
2. 使用程序获取微软官方媒体创建工具。工具不是完整 ISO：本人在微软窗口确认许可并保存 ISO，再回到程序选择该文件。
3. 点击“读取镜像版本”。程序准备已核验的 PowerShell 7，临时只读挂载 ISO，用微软 DISM 读取版本、架构与索引，并卸载本次挂载。选择许可对应的 Windows 11 x64 客户端版本；不要求手填索引。Windows 10、Server、ARM64、Linux 和无法识别的介质不会进入此安装流程。
4. 核对该版本的官方许可与虚拟机使用授权。更换镜像 / 版本后旧勾选取消；勾选不授予许可证，不激活 Windows，也不证明 ISO 是微软签名的原版。组件许可与系统许可分别显示。
5. 导入自己的订阅 / 配置或手填节点，明确选择一个节点和它的实际地区、时区，也可选择稍后配置。只传选中节点，不复制主机整份订阅和浏览器资料。
6. 保存独立的来宾账号密码，开始部署。必要的许可、UAC、重新启动、VMware 加密、AdsPower 登录 / API 权限与 Claude 验证码仍由本人处理；程序给出对应指示并保留任务。
7. 自动步骤回读后，在专用浏览器访问 `https://ip.net.coffee/claude/`，检查出口、DNS、WebRTC、时区，再本人登录 Claude 并对话。安装报告不会冒充账号和浏览器业务验收。

记住资料使用当前 Windows 用户的 DPAPI。换电脑部署应新建任务、重新输入自己的资料，不复制其他人的私有目录。应用关闭后受控网关停止，来宾没有 NAT / 直连兜底；重开应用后载入原任务继续建立保护。

## 双重防护与主机影响

外层网关只拨号到本次固定的公网 IPv4 节点和 TCP 端口，动态拒绝主机网段、私网、回环、链路本地、保留地址与 IPv6；不提供任意公共 UDP 或主机 DNS 代查。采用 15 秒租约、5 秒续期；边界回读失败、配置改变、应用退出或租约过期会撤销已有连接。Hyper-V 将安装与持续检查分成独立管理通路，避免长安装阻塞续期。

内层保留原 Clash 服务、TUN、来宾默认拒绝、所选节点精确放行、出口地区 / IP 与停止代理 / 恢复检查。业务 DNS 经所选代理。其他软件有联网需要时仍按软件补充必要规则，不能通过放开全部出站解决。

Hyper-V 基本会话保护涉及**整台主机**的增强会话策略，可能影响其他 Hyper-V VM；程序先说明并单独请求确认，记录原值与各任务归属。所有相关环境正常关机并撤回保护后，可恢复原值。VirtualBox 只添加所需进程与端口的局部规则。不会改主机代理、防火墙全局默认策略或自动关闭其他应用。

默认禁用虚拟化组件的系统级共享文件夹、剪贴板、拖放和 USB / 设备重定向。桌面左侧可主动发起双向纯文本剪贴板传送，目标仅限当前任务的来宾，待 Windows 登录且来宾工具和部署资源就绪后可用。Hyper-V 关闭 KVP 数据交换并清理已知缓存，VMware 禁用 HGFS / getHostInfo；管理和虚拟设备仍属于信任边界。不承诺隐藏一切硬件 / 虚拟化特征、账号关联或不存在逃逸漏洞。

## 开发与验证

Windows 开发机需要 Go 和 .NET 10 SDK，离线 PowerShell 测试需要 `pwsh`：

```text
python installer/build.py --test --ui-test --publish
```

SDK 不在 PATH 时传入 `--go` / `--dotnet` 的实际路径。构建脚本生成网关，获取并校验官方未修改的 Wintun 预编译包，生成来宾辅助程序，收集实际 .NET 运行库、YamlDotNet、Go 依赖与 Wintun 许可，再嵌入自包含桌面程序。构建产物在已忽略的 `installer/artifacts/Claudome-publish`，约 107 MB；Windows ISO 和虚拟化软件在线准备，不塞进 EXE。

## 2026-11-17 文档配置补齐

`aligned1` 补齐原文档中的两跳 `dialer-proxy`、浏览器运行回读与独立验收入口。网络页选择最终出口，链式区域明确选择前置；外层网关只放行前置地址和端口。直接引用独立前置节点的两跳配置可导入；动态策略组、多跳和循环会要求拆开后明确选择。部署前按原名称刷新订阅，找不到所选节点时停止，不自动换节点。地区与时区按最终出口填写。

AdsPower 使用原专用环境，设置各地区请求语言（美国为 `en-US,en`）、WebRTC 禁用、城市时区和自动匹配内核。中文网页翻译在同一浏览器的语言设置中单独设置并回读；接口不支持时保留准确待办。检查会测量真实请求头、页面语言/时区、UA 与实际内核主版本，以及仅使用本地 ICE 的候选情况；公网 DNS/IPv6 等仍需指定检测页实测。

“检查已配置环境”先读持久文件与实际内核运行信息，不重写配置。窗口原本关闭时会按官方 API 正常关闭重开后再次读取；原本已打开时保留窗口并提示保存后另做重开检查。“断线与恢复检查”分别验证桌面请求与同一专用浏览器，确认实际内核停止、请求失败以及恢复后出口正确。“重启虚拟机并检查”经用户保存工作确认后请求正常重启，要求启动时间改变并在修复配置前回读；重新登录后可继续检查，避免重复重启。

Clash 开机入口有独立备份和回退。修复了原配置流程占用 PowerShell 只读 `$HOME` 的错误。配置、浏览器运行、重开、断线、重启和人工业务验收分别记录；离线测试不记为客户实机通过。

详细实现、测试证据和客户实测范围见 [文档配置补齐与验证](文档配置补齐与验证_2026-11-17.md)。


## 本轮体验问题修复与统一桌面

`unified1` 将全局导航与当前步骤放在同一个左侧栏，右侧承载原虚拟机的真实控制台 HWND。代码按本机组件路径和任务身份定位窗口，Windows 10 2004+ / Windows 11 x64 使用同一套逻辑；不是依赖开发者电脑的固定窗口号。VirtualBox 与 Hyper-V 提供内嵌连接；VMware 原部署能力保留，其多窗口控制台嵌入仍单列为未完成项。虚拟化组件、Windows 镜像和虚拟磁盘仍需正常安装/落盘，Windows 授权和宿主 UAC 由本人完成。

继续部署按原任务里程碑恢复，已开始的 Windows 安装不重新创建；已验证且配置未变的网络可复用。原配置与浏览器环境通过回读继续，缺失的来宾文件只撤销传送检查点。订阅逐节点解析并传递原证书选项，未导入项有独立说明。共享剪贴板等隔离设置逐项报告，关机且已确认范围的任务可恢复既定值。

首次创建时填写的 CPU、内存、磁盘参数真实传入后端；已有任务的新建字段锁定，CPU/内存在单独的关机后入口调整并回读。持续黑屏提供只读诊断及兼容对照提示，未自动改动主机 Hyper-V、VBS 或安全设置。Windows 就绪后，左侧显示 Clash、AdsPower、同窗口检测页和本人登录的检查顺序。

Windows 10 兼容性是本项目的开发适配范围，不代表微软对全部 Windows 10 版本仍提供同等支持；实际客户机、跨进程 DPI、真实键鼠输入和后台黑屏恢复均需实机验收。详见[体验问题清单与修复](体验问题清单与修复_2026-11-17.md)。

## unified4 自动桌面、安装网络与任务保存

按已安装组件路径和任务身份自动接入原控制台，补齐 VirtualBox、Hyper-V 与 VMware 的适配分支；关闭原控制台后停止自动重开。VMware 和 Hyper-V 的本轮控制台变化尚未完成实机验证。VirtualBox 的 Windows 首次设置阶段新增经所选节点的临时安装网络，来宾工具就绪后立即撤销，再检查来宾 Clash。

每 15 秒原子保存部署任务，保留一份有效旧记录；正在任务中关闭助手时，可继续任务或保存并暂停后退出。左栏增加 Windows 设置与 AdsPower 检查事项，语言、地区、键盘、联网、账号、隐私、更新和来宾工具分别提示；软件阶段核对 Windows 指纹、ip-api、WebRTC、语言时区、Clash 与同窗口检测。详情与未验收范围见[修复与验证记录](自动桌面与安装网络修复_2026-11-17.md)。


## unified5 安装 DNS 检测与桌面等待状态

针对本人重试产生的 BOOTSTRAP_DNS_FAILED，新增两个独立 DoH 服务经同一个所选节点查询：固定公网拨号地址，HTTPS 使用服务域名验证；不借用主机 DNS 或直连。保留 SOCKS 认证、代理连接、HTTPS 证书、传输、服务响应和超时的固定错误码，避免把全部失败都认定为坏节点。桌面页增加“继续原任务并连接”，展示当前操作和下载进度，暂停/失败时同步右侧状态。详见[本轮证据与待实测范围](安装网络DNS与桌面等待修复_2026-11-17.md)。


## unified6 Trojan 的 TLS 服务器名

修复 Trojan 链接被写成 servername 导致内核忽略原 SNI 的错误，正确生成 sni；旧任务及前置节点在生成配置时兼容转换，保留原地址、密码和证书选项。实际 Mihomo 与回环 Trojan TLS 服务已复现旧写法握手失败、生产解析输出修复后完成网页传输。内核上游错误增加有界、固定类别的本地脱敏说明。详见[复现与修复记录](Trojan服务器名修复_2026-11-17.md)。真实节点仍待本人继续原任务验证。

## unified7 Windows 首次设置联网

DNS 和 Windows 联网页面分开检测。每段开始前重新核对并续期保护通道。网页请求尝试当前解析得到的多个公网地址，要求返回 Windows 检测所需的内容。检测通过后，来宾短时优先收到已验证地址，缓存遵守上游 TTL。等候来宾工具期间若保护通道失效，程序报告中断并保留当前进度。

最终体验包通过 309 项程序检查和 42 项网关测试。其中整链测试使用真实 Mihomo、回环 Trojan 与 HTTPS DNS 服务，以及模拟来宾的 UDP DNS 与以太网 TCP。真实虚拟机的 Windows 首次设置、桌面操作、Clash 和 AdsPower 尚待验收。
