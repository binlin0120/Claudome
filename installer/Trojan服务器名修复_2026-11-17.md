# Trojan TLS 服务器名修复（unified6）

## 已复现的代码错误

unified5 实际重试得到 BOOTSTRAP_DNS_TRANSPORT_FAILED，说明经所选节点建立的 DNS HTTPS 流中断；该码本身不能区分上游 TLS 握手与 DNS 传输。

进一步检查发现，Trojan 链接的 sni / peer 查询参数被导入为 servername。当前使用的 Mihomo 1.19.34 中，TrojanOption 读取 sni，而 VMess / VLESS 使用 servername。Trojan 未得到 sni 时回退到 server，因此当线路入口和 TLS 服务器名不同，原设置会丢失。之前的 URI 测试也错误地将 servername 当作 Trojan 的预期结果，只检查字段而未覆盖真实内核握手。

## 本机原生前后对照

使用核验过的原版 Mihomo、虚构口令、本机 TLS Trojan 服务和本机 SOCKS 客户端，所有连接均在回环内，无真实节点或虚拟机操作。

- 旧 servername 字段：本机服务拒绝错误/缺失 SNI，TLS 握手失败，无法读取网页内容；真实内核记录 tls: unrecognized name。
- 修正 sni 字段：服务接受预期 TLS 服务器名，校验 Trojan 认证及目标头后返回网页内容，客户端成功收到完整 HTTP 200 响应。
- 最终对照中，正确节点来自最终 EXE 自测实际输出的生产解析结果，不是重新手写同一份预期配置。只将服务器/端口改为本机夹具，并为测试证书显式使用夹具选项；生产配置的证书选择另有回归验证，未放宽。

该对照确认代码错误可以造成这类连接中断，但不证明真实节点除此之外没有问题。真实节点仍由本人在新版继续原任务验证。

## 代码调整

1. Trojan URI 按协议生成 sni；VMess/VLESS 保留各自的 servername。
2. 兼容导入及旧任务保存的 Trojan servername，使用原值规范化为 sni；两字段冲突时明确报错，不猜测或覆盖。生成核心配置时对最终出口和前置节点均规范化。
3. 密码、地址、端口、证书校验、链路关系及地区保持原值，原盘和安装进度保留；无需重建虚拟机。
4. 临时内核的上游拨号警告在本地按固定类别解析：证书、TLS 握手、认证、解析、拒绝、网络不可达、超时、WebSocket 或对端关闭。原始日志不落盘、不回传；单行缓冲有界，监听器健康检查消息不当作上游故障。

## 验证与交付

最终 EXE 的标准检查 309 项通过、0 失败（C# 182、WPF 37、PowerShell 89、VirtualBox CLI 契约 1）。新增覆盖 Trojan URI 的 sni/peer、旧任务两跳、冲突、VMess/VLESS 字段及脱敏分类。既有 Go 网关未修改，沿用上一轮 35 项测试结果。
