# Claudome 客户反馈处理（2026-11-16）

> 历史记录：下文描述当时的构建与测试。当前审查结论、修复及发布阻塞项见[发布前审查与修复（2026-11-17）](发布前审查与修复_2026-11-17.md)。

本次客户截图为 Windows 11 专业版、15.4 GB 内存、空闲约 9.3 GB，未安装 VirtualBox / Workstation，Hyper-V 注册接口未读取成功。

## 已确认原因

| 客户现象 | 源码确认 | 处理 |
|---|---|---|
| 最后一步提示“隔离边界尚未达到部署条件” | `IsolationPolicy.RequireExternalBoundary` 对所有实际部署主动抛出异常；不是客户当前这次操作导致，也不是截图中内存不足所致 | 承认交付尚不能部署的版本不满足成品要求；本轮不以另一个预览包替代正式版。保留真实验收前的部署限制 |
| 下拉框出现 `PlatformChoice { Id = ... }` | 自定义 ComboBox 模板的选中项没有传递 `ItemTemplateSelector`，导致记录对象使用默认文本；Popup 也未命名为框架识别的部件 | 补齐内容选择器、字符串格式与 `PART_Popup` / `ItemsPresenter`；11 项实际 WPF 渲染检查验证平台、国家、时区、节点与确认文案 |
| 专业版推荐 Hyper-V，但确认框写 VirtualBox | 确认文字硬编码 | 按所选平台生成确认范围 |
| 已是专业版却提示 Hyper-V 不可读 | 系统版本条件与功能启用、服务可用、账号权限是不同条件；旧扫描吞掉了具体错误 | 区分 WMI 权限拒绝、管理接口 / 类不可用及超时。客户截图本身不足以确定其中哪一种 |
| 下载到 20.6 MB 后仍不能部署 | 20.6 MB 进度是微软媒体创建工具，不是完整 Windows ISO；安装拦截又是独立的版本限制 | 按钮改为“下载并打开微软镜像工具”，明确工具与 ISO 的区别；缓存复用回报真实资源与大小，避免沿用上一项进度 |
| 反复点击“继续”仍提示同一错误 | 开发验收并非客户能完成的手动步骤，旧提示错误地暗示跟随右侧操作即可解除 | 改为明确版本限制；对应待办不再提供无意义的继续 / 打开按钮 |

WMI 错误码解释对照 [Microsoft 官方资料](https://learn.microsoft.com/en-us/windows/win32/wmisdk/wmi-error-constants)。仅凭用户截图不宣称已经远程检查或修复了客户电脑。

## 同时补充的安装流程修正

- 应用打开虚拟机前重新确认 VM 归属、外层规则与适配器。
- 保存 / 暂停状态保留原网卡绑定，验证一致后恢复，不改写不可变的保存设置，也不丢弃保存状态。
- 离线安装任务允许在全部网卡关闭且回读通过后进入应用打开路径；存在网络通路则拒绝。
- 增加安全诊断导出：仅系统条件、构建版本 / 可执行文件指纹、注册数量与安全错误说明；不导出 VM 名称、配置路径、主机用户名、真实节点或账号。
- 预览验证不载入本机已保存任务，采用虚构场景，避免只有开发电脑上特定状态才能得到正确界面。

## 本轮边界

用户明确选择“仅继续开发，暂不在本机安装”。因此本轮只做源码修改、编译和离线 / 只读验证。没有安装 VirtualBox、创建来宾、应用主机防火墙规则、导入真实订阅或发出新的客户安装包。

正式版仍必须完成实机安装、应用打开窗口、来宾软件、节点、AdsPower 及双层隔离验收。离线通过不代表这些已经完成，不通过更换版本名称来发布。

## 2026-11-17 完整部署开发与许可提示更新

旧版本把未完成的开发验收当作客户手动步骤，确实不能满足可用成品要求。当前已补齐三平台受控网络接入，并改为真实配置回读，不再无条件阻断所有部署。新的开发 EXE 仍未作实机安装验收，不以更改版本名称冒充正式成品。

用户补充的“同意许可”截图显示安装范围文案被截断；旧文案也只随虚拟机平台变化，没有读取所选系统镜像。现保留 TextBlock 换行，按实际识别的 Windows 版本显示系统使用授权和安装范围，切换版本 / 镜像取消旧勾选。不支持的系统与无法识别的镜像不进入当前 Windows 11 x64 流程；勾选不授予许可证或激活系统。

镜像识别、Hyper-V 交互桌面调度、安装 / 回退报告防旧结果误用、刷新界面误关闭网关等一并修正。当前验证结果和开发产物见[完整部署接通与验证](完整部署接通与验证_2026-11-17.md)。此轮仍未安装或启动真实虚拟机，也没有应用真实网络规则。
