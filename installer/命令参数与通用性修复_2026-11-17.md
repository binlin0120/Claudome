# 命令参数与通用性修复

版本：`0.4.0-dev.20261117.unified2`。

## 本次提示的原因

原任务 UUID 与配置目录一致，磁盘文件保留，读取时虚拟机状态为关机。共享剪贴板读回为 `hosttoguest`，因此继续部署会进入隔离恢复分支。上一版在该分支使用 `--clipboard-file-transfers off`，而本机 VirtualBox 7.2.22 及官方 7.2 文档要求修改命令使用 `enabled/disabled`；机器信息中的 `on/off` 是另一种读回表示。公共命令执行器又丢弃了原错误内容，仅给出泛化提示，掩盖了错误位置。

这是共享代码路径的问题，其他 VirtualBox 任务进入同一分支也会触发。修正为 `disabled`，不改动任务身份或以具体 VM 为特例。Hyper-V 与 VMware 不调用此参数，保留各自后端语法。

## 通用性检查

- VirtualBox：使用注册表及系统组件路径定位；所有任务共用参数修正。新增严格模拟 CLI 参数校验，以及只读取已安装组件帮助的独立格式检查。检查能拒绝旧写法，修正后通过。
- 范围控制：保留 UUID 与目录核对；增加关机但未确认范围、相同 UUID 却属于不同目录的拒绝测试。这些情况不发出修改命令。
- Hyper-V：继续使用结构化管理通道。失败信息增加固定的操作名称和受控代码，映像写入、启动文件、来宾命令失败有明确说明；不输出未知的原始异常字符串。
- VMware：CLI 失败保留操作与退出码，VIX 失败保留操作与数字错误码，来宾命令返回值也会保留；没有改动 SDK 调用方式或套用 VirtualBox 参数。
- 错误提示：固定操作名称与已知错误标识可显示，原始命令行、标准错误、文件路径、订阅和账号参数不直接显示。

新增的真实进程测试最初错误假定 PowerShell 安装在默认目录，已改为按系统目录寻找 Windows 自带只读工具，避免客户机依赖开发环境。测试记录及修正前后 CLI 比较保留在 `output/命令参数修复_2026-11-17`，原测试与交付包没有删除。

本轮只读取真实任务的非敏感状态及本机组件帮助；没有启动、关闭、重启、修改真实 VM，也没有改宿主网络或安全功能。当前仓库部署会话为 Locked，源码维护、合成测试与打包在其允许范围内。

实机验收仍需分别覆盖 Windows 10/11、VirtualBox/Hyper-V/VMware、不同安装路径和 DPI、暂停/保存/关机/运行状态、Clash/AdsPower 与业务检测。此前黑屏尚未证实解决，VMware 控制台嵌入仍未完成；不能将本轮离线通过写成所有机器均已验收。
